# Core governance

- The current milestone dominates. Production changes must directly advance it or remove a blocker.
- Classify new ideas as `CURRENT_BLOCKER`, `NICE_TO_HAVE`, `RESEARCH`, or `FUTURE_FRAMEWORK`. Only blockers enter immediate implementation.
- Prefer the smallest deterministic solution matching acceptance criteria.
- Research produces notes/backlog items; it does not imply implementation.
- Preserve verified paths and require real evidence before architectural change.
- Mode and gate requirements constrain every task.
